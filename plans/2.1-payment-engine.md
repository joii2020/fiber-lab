## 当前事实

SDK 支持持久化精确金额授权、双 commitment lane 核验、撤销及安全秘密释放。租户 RPC 支持 hold invoice 与付款，查询可能唤醒租户。SDK 付款授权要求通道 TLC 金额精确相等，不能只记录费用上限。

原实现事实（多用户改造前，历史依据；当前实现及验证见 2.1.1）：

- `fiber-lsp-client/src/accounts.rs` 的清单版本为 1，只有全局 `current` 和 `accounts[{id, archived}]`；只能有一个未归档的默认账户，不能直接把四用户挂在现有 `current` 下。
- `account.rs` 已有独立身份初始化、恢复、注册及持久化；`ClientAccount` 持有账户锁。当前显式指定未初始化账户不会执行 `initialize`，须改成受用户归属控制的初始化入口。
- `admin.rs::init_lsp` 目前同步修改 YAML 和密钥；`scripts/create.sh` 在它之后才生成 token、启动 LSP。新增 `init-accounts` 插入这两步之间，复用离线本地身份初始化，不依赖租户 RPC。
- `channel.rs` 保存单账户开关意图，`close_inner` 已等待关闭交易链上确认及核验双方退款；它既可能返回“无通道”，也可能返回已核验关闭。保留原核验与等待流程，仅为归档编排区分结果。
- `wallet.rs::Wallet::load` 固定客户端 #6，但 `Terms.wallet_account` 已支持保存钱包编号，签名及关闭会按保存条款恢复；新开通改为接收用户绑定即可沿用大部分核验。
- 当前只读账户选择也会调用 `Registry::save`；改造后的列表及查询选择路径应避免无变化写回。
- 本地 Fiber 依据：`../fiber/crates/fiber-lib/src/lsp/registry.rs::bind_private_channel` 拒绝将租户改绑其他通道；`../fiber/crates/fiber-lsp-sdk/src/session.rs::begin_channel_opening` 只允许已有 binding 重试同一请求。

## 技术要点

- 新 Rust payments 模块复用账户锁、私有文件原子写入与 SDK store。payments.json 保存原始意图、授权、秘密及状态；查询仅读取，不修改 SDK。
- 本地 fiber-types 解析并核验签名、网络、金额和资产；付款显式通过 Public T trampoline，通道授权金额为发票金额加原费用预算，固定预算同时传入 max_fee_amount 和足够的 max_fee_rate，max_parts=1。路由不能改变本地精确授权。
- 提交前保存意图；付款发送前记录可能已发送，响应丢失后只 get_payment 核对，不自动再次发送。创建响应丢失先按 hash get_invoice，明确不存在后复用原 hash 创建。
- 签名只允许 commitment 与 revocation，经 SDK 必须验证器验证。保存请求和响应用于提交重放；安全释放每次使用独立 CKB live funding 校验和当前时间。
- 成功需远端 Success / Paid、SDK 两条 lane 的 TLC 移除证据及远端余额一致；单纯远端成功不能报告本地完成。
- 关闭使用双方最新 SDK 已验证余额，不再假定原注入余额；归档保留 payments.json。
- watch 前台持续推进，resume 有界推进；Ctrl-C / 超时保留原授权，不取消网络操作。查询不借用管理 token。

### 多用户与通道编排

1. 清单升级为版本 2，区分固定用户、当前账户、最近关闭账户和永久历史归属。用户创建的账户一经指定 owner 就不可更改；tenant_id 注册成功后同样不能转移用户。账户目录仍按原 ID 寻址，归档不更改 SDK 路径或 owner。
2. 新增独立 `admin init-accounts`，仅复用本地 SDK 身份创建；`admin init-lsp` 保持现有同步配置入口。注册沿用现有 nonce、凭证和响应核验流程。`create-channel` 编排注册与开通时使用同一个已选账户和锁，不通过嵌套 CLI 调用实现。
3. 钱包绑定保存 offckb 编号及公开 lock script，address 用于展示。新开通校验运行时 offckb 信息与绑定一致，原通道恢复以 `Terms` 为准；只在出资签名时读取对应私钥，不复制到用户清单。
4. 引入用户级锁覆盖选择、注册、开关和归档全流程，避免下一轮与归档竞争；账户锁继续保护 SDK。注册表锁只覆盖本地元数据读改写，不跨 RPC 等待。
5. 新开通增加项目级开通锁，覆盖原通道开通推进的整个命令，包括恢复；获取失败提示另一次开通正在执行。不做并发资金 cell 预留服务或自动重试交易。
6. 保留关闭引擎现有等待链上确认和退款核验的逻辑，返回结构化结果供编排层使用；只有 `ClosedVerified` 才追加幂等归档。归档写入失败单独提示“资金已关闭，归档待恢复”，退出非零，重试同一关闭命令即可补齐。
7. 收付款模块只调整选择入口和恢复提示，授权及历史仍按账户 ID 隔离，不把四用户的数据合并成一个共享 `payments.json`。

## 风险与依赖

通道 TTL、发票有效期、CLI 等待超时不同。SDK 拒绝过期 TLC 或不足恢复窗口时不得绕过。真实 Deferred 由现有管理操作构造，CLI 退出仅停止客户端签名。发送结果未知且服务端无记录时保留未知，不以重发消除不确定性。

用户共享 LSP #5 出资 cells，新开通需串行以避免选中同一 live cell；不同用户收付款可并行，同用户继续互斥。归档不注销租户或释放服务端租户名额，不自动清理历史；旧 #5/#6 通道必须按原条款恢复。

本级复用已交付的收付款代码，不将尚未完成的真实验收当作已通过，也不另设一个独立方案作为新前置。新增多用户已授权、已实现并完成真实生命周期验证；真实付款暴露新的服务端证据时序/超时前置，详见草案，现授权不能修改服务端。
