## 目标与背景

本项目用于探索 Fiber LSP，后续将整理为教程。将 `lsp-cli` 定位为“Fiber LSP 联调工具”，通过一个入口提供管理操作和客户端操作，减少教程中重复的 Shell 文件操作，同时保留协议和权限的解释。

现有 CLI 仅提供 `create-user` 和 `status`。其中 `create-user` 已经使用管理 token 调用注册相关 RPC，注册后使用用户凭证操作账户。README 的“生成 RPC 管理凭证”通过 Shell 写入权限文件，再调用外部 `biscuit` 签发 token。

首期将管理 token 签发迁入 CLI。运行环境继续由 offckb 管理 CKB devnet 和普通节点，Shell 单独启动 LSP。

## 工具与命令职责

| 入口 | 使用者与职责 | 首期处理 |
| --- | --- | --- |
| `lsp-cli admin create-token` | LSP 操作者：使用服务端 Biscuit 私钥签发管理凭证 | 新增 |
| `lsp-cli create-user` | 联调操作者：创建或恢复客户端账户，首次注册使用已有管理凭证 | 保留现有命令和行为 |
| `lsp-cli status` | 客户端用户：使用用户凭证查询当前账户通道数量 | 保留现有命令和行为 |
| offckb 与 `scripts/` | 本地环境：初始化、启动、停止 CKB 和 Fiber 节点 | 保留现有分工 |

管理命令显式读取服务端私钥。客户端命令继续只读取所需的管理 token 或用户凭证，不自动读取服务端私钥、不自动签发管理 token。

首次注册需要管理凭证属于当前实验环境的接入方式。教程需要解释操作者执行注册与用户后续操作的区别；面向普通用户的注册服务设计不在本期范围。

CLI 帮助和 README 使用“Fiber LSP 联调工具”的名称。入口 `./lsp-cli`、Rust 包名 `fiber-lsp-client`、现有目录和账户路径保留，避免本期引入迁移。

## 首期命令设计

教程中的标准调用：

```bash
./lsp-cli admin create-token
```

参数约定：

- `--config`：可选，默认读取当前 offckb devnet 的 Node3 配置，即 `${XDG_DATA_HOME:-$HOME/.local/share}/offckb-nodejs/devnet/fiber/nodes/3/config.yml`。目录推导与 `scripts/config.sh` 保持一致，由 Rust 直接计算，不要求提前 `source` Shell 脚本，也不读取可能尚未复制或已过期的 `configs/lsp.yml`。签发不要求配置 RPC 地址或连接服务。
- `--private-key-file`：可选，默认读取所选配置的 `rpc.biscuit_private_key_path`；当前教程已要求该字段保存 Node3 私钥的绝对路径。显式提供时覆盖该字段；相对路径相对于当前工作目录解析。读取完整的 `ed25519-private/...` 字符串，允许末尾换行；私钥不通过命令行参数直接传值。字段缺失时提示补齐配置或指定参数，不猜测其他私钥位置。
- `--output`：可选，默认写入项目内 `configs/keys/operator-token`，与客户端现有读取路径一致。显式相对路径相对于当前工作目录。
- 不提供覆盖选项。目标文件已存在时返回明确错误并保留原文件；重复执行不自动轮换凭证。

默认项目路径沿用现有 CLI 定位项目根目录的方式；将工具变成可脱离源码目录安装的通用程序留待后续规划。

三个参数均作为可选覆盖项保留，便于联调其他节点或使用临时输出文件。正常教程流程只执行无参数命令；签发前的帮助说明默认路径和解析规则，成功后显示实际配置路径及输出路径。显式指定的配置缺失或无效时直接报错，不退回其他配置。

固定签发以下管理权限，在帮助、文档和成功输出中列出：

```text
read("lsp");
write("lsp");
read("node");
```

首期不支持任意 Datalog 输入、权限模板或过期时间参数。权限保持与现有教程一致，明确该凭证可读写 LSP、读取节点信息；它不授予 `write("node")`。

成功时输出保存路径、权限和完成提示，不输出私钥或 token 正文。失败时提供可操作的错误信息，错误与调试输出不包含秘密内容。

## 实现方式

1. 重构命令解析，采用 `clap` 表达子命令、参数和逐级帮助；保留现有两个客户端命令的调用形式以及无参数显示帮助的行为。先分发命令，再读取各自所需配置，避免管理命令依赖客户端账户或完整客户端配置。
2. 新增 `admin.rs`，封装 offckb Node3 默认路径推导、配置公钥及私钥路径读取、参数覆盖、私钥解析、公私钥匹配校验和管理 token 构造。使用 Rust 的 `biscuit-auth` 库，依赖版本与同级 Fiber 使用的版本约束一致，实施时核对其实际 API 和 token 编码。
3. 签发前校验公私钥匹配；使用 Fiber 接受的 token 格式保存，并保持现有 `operator_token()` 的读取方式可用。签发全程离线，不要求 LSP 已启动。
4. 增加适用于首次创建凭证的文件写入函数：创建必要的输出目录，token 文件权限设为 `600`，完整写入并同步后以不覆盖的方式发布。拒绝已有目标和符号链接目标，并处理并发创建。现有 `store::atomic_write` 会替换文件，不能直接用于此次首次签发。
5. 私钥读取遵循现有私密文件约定：要求仅当前用户可访问的普通文件，错误时说明如何调整权限，不擅自修改源私钥。私钥文本使用现有 `zeroize` 能力管理；异常中不附带文件正文。

本期不新增密钥生成或配置修改能力。README 继续使用 `biscuit keypair` 生成密钥，因此本期仍保留 `biscuit-cli` 的安装说明。
