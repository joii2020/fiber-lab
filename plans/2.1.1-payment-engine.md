## 涉及代码及接口

## 详细技术设计

payments.json 版本化，账户 / 通道归属绑定；每笔记录保存方向、hash、amount、max_fee、SDK PaymentAuthorization、invoice、preimage（收款）、创建及发送提交标记、远端原始状态、更新时间、本地完成证据。所有写入受账户锁保护，秘密文件 600。

先写本地意图再写 SDK 授权，再发网络请求。重启重放相同 SDK 授权；不可替换条款。发送提交标记落盘后只查询恢复；新发送只限尚未提交的原意图。创建按原 hash 核对响应并本地重新解析 invoice_address，验证 hash、金额、有效期、算法、收款人及 trampoline hint。

推进顺序为恢复授权 / 原创建 → 核对所有原操作与可验证的 fulfillment / cancellation → 校验签名请求并保存 / 提交 → 入账 TLC 获得完整本地证明后授权释放并立即 settle_invoice → 再核对双 lane 和 RPC 余额。收款不能因发票 Expired 推断已接受 TLC 失败。每次 settle 重试重新执行安全释放校验。

查询不持久化远端响应，不输出远端原始错误、preimage 或凭证；远端不可用仍输出本地记录。resume 只定位目标，签名推进允许同通道其他原授权；watch 持續前台。全命令支持账户和配置；timeout 仅停止本次等待，Ctrl-C 同样保存恢复信息。

关闭条款持久化最新无 TLC 的 SDK 双 lane 余额，远端余额加 reserves 必须匹配；退款减关闭费后按原出资脚本核对。
